# 复利第二环 · 框架摘要（v0.1.0）

> 性质：模板原件里的框架摘要，只留能搬走的骨架。正本是运行件那边带日期的设计稿（随复盘样本在改）；两处不一致以正本为准，路径见套装 README 的对应表。
> 读法：聊这件事读 §0–§5；复盘一件事读 §6 + `templates/A-sample.md`；接人际线读 §7 + `templates/LINE.md`；派活与交接读 §8–§9；判一样东西在不在用读 `in-use-criteria.md`；探针怎么跑读 `probes-howto.md`。

## 0 一句话

**复利 = 每一次上场都让下一次的起点更高。**

执行 ⇄ 验收闭在一件事里面，是第一个环。复利是套在外面的第二个环：入口是「这件事干完了」，出口是「下一件事开场时它到场了」。**复利不换验收线的轴**：验收线只对当前任务，一个字不动；第二个环是叠加上去的机制。

「凭什么不白干」的答案 = 第二个环有没有真的转 + 转了有没有读数。

## 1 第二个环长什么样

```
第一个环（一件事里面）          执行 ⇄ 验收（只对当前任务；不动）
                                     │ 干完
第二个环（一件事与下一件之间）   记录 → 提炼 → 归位 → 到场 / 取用 → 反馈
                                     └────────────────────────────────┘ 增量写回，起点抬高
```

| 步 | 干什么 | 常见载体 |
|---|---|---|
| 记录 | 过程留痕：谁动、什么动作、对什么、之后球在谁 | 会话轨迹账本、带日期的观测件 |
| 提炼 | 从原话或产物到「可带走的」那一步 | 提炼队列一行、黑匣子三行、回归测试、会面复盘 |
| 归位 | 放进它该在的家 | 归位三法则：**产出归位**（判断 → 判断层；状态与证据 → 项目仓；工具 → 独立目录；环境结晶物 → 项目状态件，记忆只留一行路由壳）· **到场归位**（存哪 ≠ 从哪到场；跨项目经验的到场位是入口的记忆 / 路由，不复制进各项目）· **入口唯一** |
| 到场 / 取用 | 下一件开场时被注入，或被检索到 | 记忆索引一行路由壳、开场注入、判断层检索 |
| 反馈 | 用完的增量写回，回到提炼 | 「第四步回到第二步」 |

这个环不是新维度，也不新建模块：是把「过程 = 时序」的尺度从一件事里面换成一件事与下一件事之间。

## 2 四条线

第二个环上跑的不是一条线，是四条。每条线的复利类型、提炼方式、用途、家、探针都不同，不能用一套「都再挖一遍」对付。

| 线 | 复利的类型 | 家（归位） | 提炼方式 | 用途 = 下一次上场 | 「用上了没」的探针 |
|---|---|---|---|---|---|
| **认知线** | 判断、方法、SOP、案例（给自己下一次用） | 判断层正本；可触发的方法（skill）；项目侧缓存（记忆，只留路由壳） | 收尾时提炼队列一行 → 判断层入库；黑匣子当场写；记忆里的稳定判断收尾时回扫进提炼队列 | 下个项目开场到场、查库先于动手、同题不重推 | 同题第二次出现时，第一次的沉淀被召回并用上 |
| **资产线** | 工具、作品、交付物、对外材料（给别人看、别人用） | 资产清单 + 各工具目录 + 交付件所在目录（交付件常住在别的分组里，清单要登得到仓外） | 立项门槛 → 资产卡；对外先脱敏 + 红队（这是元运维产物转资产的门） | 复用工具、对外作品、见面材料 | 被真实需求方使用（尝试 ≠ 作品） |
| **元运维线** | 工作台自身的架构判断、断点读数、修复 + 回归测试、假声明清单 | 架构文档、观测件、拍板账本、修复日志、回归测试 | 口述对读、对抗审计、拍板当场落盘、后置兜底测试 | 下次设计不重推；下次审计只换输入；真跑读数可信 | 「同题问第 N 遍」 |
| **人际线** | 对一个人的理解、关系本身、我学到的、我分享的、共同经历；**也包括 AI 对用户本人的理解** | 人机关系分组目录本身 + 每人一份 `LINE.md` 住他现有目录 + 关系网索引 + 会面复盘；对用户本人 = 协作画像 + 纠偏记忆 | 会面复盘（事后）、会话标签（机械）、四层回写（每次接触后）；对用户本人：**被纠正当场回写**，与「他说特别舒服时回写样本」对称 | 下次见面更懂；方案「他没说全但接住了」；下一条需求直接辨认新增 / 修改 / 已有 | 对方愿不愿意再来；「对，就是这个意思」 |

**边界**
- 认知 vs 资产：**看那一次谁在消费**。自己下一次上场用 → 认知；别人看、别人用 → 资产。给自己用的 SOP 归认知，交付出去的那份才是资产；同一件东西可以同时在两条线上。
- 设计线 = 元运维：管工作台自己的设计、审计、修复、漂移。
- 四线不是并列封闭的：一个方法从一条线学来，用到另一条线上的人和事，再报回源头，源头再升一维——这一圈是最硬的复利读数。A 模板第 8 问专门记它。

## 3 三个定义 × 四条线

| 定义 | 问什么 | 认知线 | 资产线 | 元运维线 | 人际线 |
|---|---|---|---|---|---|
| **类型** | 这件事干完能剩下哪几种可带走的 | 判断 / 方法 / SOP / 案例 | 工具 / 作品 / 交付物 / 对外材料 | 架构判断 / 断点读数 / 修复 + 测试 / 假声明清单 | 他说过的 / 我理解的 / AI 推导的 / 他反馈的（四层分开存）；我学到的 / 我分享的 / 共同经历 |
| **提炼方式** | 从原话或产物到可带走的那一步怎么做、谁做 | 提炼队列一行 → 判断层入库；黑匣子当场；记忆里的稳定判断收尾回扫进队列（样本里出过：进了记忆没进队列） | 立项门槛 → 资产卡；红队后发布 | 观测件 + 拍板行 + 回归测试 | 会面复盘、会话标签、四层回写；**初期不问「要学他哪项」** |
| **用途** | 下一次上场是什么场景、谁取用、改变哪一步、用完更新回哪 | 开场到场 / 查库 / 同题召回 | 复用 / 对外 | 防重推 / 真跑读数 | 下次见面 / 下次需求 / 下次方案 |

## 4 两本账（贯穿四线）

- **取用账**：用途已知。验收 = 下一次上场真用上了，并留下新增量。
- **线上账**：用途未知。先留下「对我来说新的东西」和当时的疑问，挂在一条线上，等交往深了、样本多了再辨认。验收 = 线变厚了、后来被辨认出来。人际线几乎全是线上账；认知线里的「课题候选」也是。**线上账要有回看节奏**——没有节奏的线上账只进不出（样本里攒到九条待问，一条没问出去）。
- 两本账不能互相冒充：用取用账的验收去卡线上账，就是「问早了」；用线上账的宽松去放取用账，就是库存。
- 报告类产物默认会变库存：报告头部写一行「下一次上场」，写不出就承认它是库存。

## 5 顺序机制

1. **一件事干完 → 它的复盘（A 模板）→ 按四线提炼 → 归位 → 下一件开场到场。** 顺序不能乱。
2. 干一件事时冒出的新角度，不接着做，进**停车场**：一行 = 想法 + 触发它的当前事 + 日期。当前事干完、复盘时取出来。这是「事中制衡」的另一半：不只在他钻细节时叫人，在他跑题时也接住，而不是跟着跑。
3. 反面样本：主会话在一件事收口时两次跟着跑题，还把跑题提成了「验收线换轴」。
4. 长线关系没有「干完」：人际线的复盘按里程碑切片。

## 6 探针：「凭什么不白干」的读数口

| 仪表 | 量什么 | 机器读数口（运行件怎么跑见 `probes-howto.md`） | 量不到时 |
|---|---|---|---|
| ① 同题第二次被召回并用上（记忆召回对账） | 认知线的终点验收 | 逐场算：人开口撞上记忆索引某行的触发样例 = 命中；同场读了那行指的文件 = 消费；命中未消费 = 漏 | 索引读不到写「不可得」，不写 0 |
| ② 注入命中 vs 消费（路由对账） | 注入的东西被用了没 | 同一份轨迹账本的路由对账节；每天对昨天的会话汇总，开场注入一行 | 昨夜没跑写「没跑」，不写 0 场 |
| ③ 判断层取用 | 判断层被查了没 | 夜里扫会话，只数真调用（不数注入文本里的示例命令），开场注入一行「昨夜 N 次 · 近 7 天 M 次」 | 无产物 / 旧格式 / 停在某天，各有措辞，都不写 0 |
| ④ 判据台账标龄 | 判据命中 / miss 的记账还活着没 | 报告首行「台账最后写入 X（N 天前）」；超期时义务类「守住」读数作废 | 死账不许印「守住」 |
| ⑤ 对方愿不愿意再来 | 人际线终点 | `LINE.md` §6 记录格 | 只有记录格，没有机器读数 |
| ⑥ 「对，就是这个意思」 | 反馈回到理解（第四步回到第二步） | `LINE.md` §6 记录格；口径 = 只算对「方案 / 理解」的确认，不算对产物的裁决 | 严格口径常为 0，照实写 |

- 「同题问第 N 遍」（元运维线的召回失败率）= ① 的「漏」列，不另设仪表。
- `LINE.md` §6 还有一格「引荐发生了没」：信任传递的读数（父母宫、交友宫）。
- 探针自己也要判「在不在用」：在跑但没人看的探针 = 环没转（判据见 `in-use-criteria.md`）。**0 是「量了、一次没用」；量不到写成 0，就是在死账上读「守住」。**
- 没有这一节，框架就是故事。

## 7 人际线展开：宫 × 人 × 两条链 × 四阶段

### 7.1 宫当坐标（不是预测）

复利的类型跟着关系位置走：每个宫回答的是「在这类关系里我是谁、对方是谁、什么东西会越滚越厚」。十二宫里属于人际的七个：

| 宫 | 这类关系里我是谁 | 这一宫滚的是什么 | 探针 |
|---|---|---|---|
| 父母宫 | 被引路者、被验证者 | 信任的传递：长辈验证过的人品，变成可以直接跟着干的网络；每接住一次引荐都给这条信任加码 | 引荐还会不会来 |
| 兄弟宫 | 同辈、至亲、合伙人 | 交付变工具（资产线）+ 对方的领域进我的库（认知线） | 「每次都要」是否持续 |
| 夫妻宫 | 伴侣 | 没有记录就留空，不编 | — |
| 子女宫 | 晚辈、学生、被我带的人；部分读法含创作产出 | 我教出去的东西活了没 | 对方用没用、回来问没问 |
| 交友宫（明刊本作奴僕，口语「仆役」） | 朋友、客户、伙计、同事 | 双向学习与共同经历：我学对方的长处，也分享我的；一笔一笔滚，不是一锤子买卖 | 愿不愿意再来；引荐了几个人；「对，就是这个意思」几次 |
| 官禄宫 | 事业里的上司、前辈、贵人 | 被看见与引路：对方给的原则、练习、作业；我交回执换下一课 | 回不回、愿不愿再聊；回执被接住几条 |
| 迁移宫 | 在外遇到的人与机会 | 新缘变熟缘：交往深了挪到交友或官禄宫 | 有没有第二次 |

财帛、疾厄、田宅、福德、命宫不属人际线。一个人可以跨宫：从某人引来的人先落迁移宫。**红线**：宫是关系位置的坐标与分类；命盘里的星与四化只当「这类关系里我的惯性提示」，措辞只许「倾向 / 提示」，终审在人，不进能力资产；人放哪个宫按关系性质放，不从命盘推。

### 7.2 分组 = 关系

人机关系分组（个人 / 工作 / 朋友 / 家人……各一格）本身就是人际线的正本载体：一个人在哪个分组 = 我和他是什么关系；宫是叠在分组上的更细坐标；以后新发现的、关于这个人的规则（约束、禁词、设备、成本敏感）也挂在那里。所以线文件住他现有目录，不另建人物库。

### 7.3 四阶段（时间轴，不是状态机）

接触新事物 → 共同经历 → 逐渐理解彼此 → 发现值得深学之处。顺序不硬、可交叠，换一个领域就从头再来。**标当前段，不标目标**；最初阶段对我新的东西都值得学，交往深了自然会辨认出值得深学的地方，**初期不问「要学他哪项」**。

### 7.4 两条链：每件具体的事上的一副镜片

「独当一面 = 搞清楚一件事的利益链和情绪链」（方法来自一位前辈的会面，出处在运行件那边）。练习本体不是画关系图，是对手头一件具体的事理清两条链，读完回写那个人的线：

| 链 | 问什么 |
|---|---|
| 利益链 | 这件事上谁得什么、谁依赖谁、谁付成本、谁的考核挂着 |
| 情绪链 | 谁怕什么、谁被什么牵着、压力从哪来、强势的背面是什么 |
| 归属 | 这句是谁说的、说的是谁（出处文件 + 轮次）；读别人先把自己的处境摘出去（样本里出过一次：把自己的处境读成了对方的） |
| 回写 | 读完对这个人多懂了哪一层（四层里的哪一层）、哪句原话支撑、有没有推翻旧理解 |

### 7.5 载体与候选

- 每人一份 `LINE.md`（模板 `templates/LINE.md`，九节固定），住他现有目录；宫图索引挂在关系网记忆的顶部；A 样本人际线那格直接引 LINE。
- 候选（未做，改共享配置属档 1）：给派活的维度与交接加一格 `for`（= 分组路径 + 宫），开场按 `for` 带那个人的线文件与约束卡；A 模板加「回写谁的线」。今天只在立项时问一次「给谁做」，之后不随任务走。

## 8 三种活分开跑

| 活 | 在干什么 | 要求 | 谁干 |
|---|---|---|---|
| **引导激发** | 讨论中把他没说出口的想法逼出来、命名、让他验证 | 举镜子、每轮 ≤2 问、拍板权在他；**想法没定型前不冻结、不当拍板落账** | 主 agent |
| **纯执行** | 按任务书把活干完，产物落地 | 不聊、不改题、每单元立刻落盘；回执写「改了什么 / 怎么验 / 没做什么」 | 主要是分身；主 agent 收口时也在这一档 |
| **沉淀过程与结果** | 一件事干完后，把过程与结果写成可回源的件 | 原话与推导分层、带日期与负空间、只记发生过的；**在事后，不在事中** | 主 agent 的复盘档，或专门一遍 |

主 agent 三档都要会，但每次只在一档，换档要说出口（「现在是在陪你想，还是在执行，还是在收尾记录」）。分身只有后两档：不引导、不替他做设计判断，遇到设计判断写进回执交回主会话。对应第二个环：引导发生在一件事开始前和复盘时的对话里；纯执行是第一个环；沉淀是第二个环的「记录 → 提炼」。混档的代价就是一锅粥。

## 9 交接契约要点：Claude 出内容与判断，Codex 出表达

谁有哪一半上下文，谁做哪一半。模板：`templates/content-handoff.md`（九节）→ `templates/codex-receipt.md`（五节）。

| 角色 | 干什么 | 不干什么 |
|---|---|---|
| Claude 主会话 | 引导、设计、判断；写内容交接包；收货验收 | 不替 Codex 定样式 |
| Claude 分身 | 纯执行与沉淀：按任务书干完、每单元落盘、写回执 | 不引导、不做设计判断 |
| Codex | 表达层：页面 / 前端 / 样式 / 交互 / 幻灯 / 报表页 | 不改内容口径与名字，不补内容 |
| 用户 | 拍板；双击看成品 | — |

1. **一次交接**：Claude 写交接包并落仓（不放临时目录，包是正本，回执要回指它）→ 经派单壳发射，或手动在 Codex 里「读这个包、照做、回执写到指定位置」→ Codex 出产物、按五节写回执 → 收货。
2. **谁验收**：开单闸（机器，只管经它派的单：包在、九节齐、回执路径写死；收单时回执不在记失败）→ Claude 主会话按包的验收清单**逐条复跑**，不只读回执，「只提了 / 没做」单列给用户 → 用户双击拍板。回执是对照表，不是验收结论。
3. **Codex 可以推翻**脚手架的任何一条和硬约束以外的呈现建议，但必须在回执写「原条 → 改成 → 为什么」；不说就是沉默的偏离，按没做算。**不许**：改内容口径（读数、状态、结论、时间线）、改名字、补内容、把页面上的勾选当授权。
4. **Claude 不许**：替 Codex 定样式（约束只写用户既有偏好并带出处）、让 Codex 直接读原始长报告自己提炼、口头派（包不落仓不派）、只读回执就验收。
5. **与其他任务型的分界**：新做或大改一个表达物、内容口径来自 Claude → 本契约；既有页面小修 → 样式型，不用交接包；只读检验 → 校验型；设计与取舍 → 不外派，留主会话。

## 10 松耦合（本套装的组装原则）

- **不做死强关联**：脚本拿已有的东西，按调度壳的规范组合查询；被查的东西按整体规范（目录结构 + 内容结构）长，才可被调用。
- **两个必须**：真的有（运行件在跑、有读数）+ 在 cg 有可加载的套装（本包）。
- **验收时每样问三句**：① 有没有写死的关联（路径硬编码、互相 import）？② 运行件真的有、真有读数吗？③ cg 里的模板能被加载吗（README 标题能被查询口列出、`install-pack.py` 能装）？
- 本包怎么守：模板里只有 `<项目>` 类占位；运行件路径只出现在 README 的对应表；机器认的是结构（节名、「> 宫：」第二行、「回执：」一行、文件名规则），不是路径。

## 11 负空间

- 本件是设计稿的压缩；四线切法是用户一句「我觉得可以，暂时没有太想好」过的，不是逐格验收，线的数目和边界随样本可改。
- 「复利」是比喻，这里不给它数学定义：能量的是探针，不是利率。
- 六块探针里四块有机器读数，都在运行件那边；别的项目没有这些运行件，复盘里这几格就是「无读数」。人际线两块只有记录格。
- 宫的含义按通行读法写，没从明刊本底本核；各宫「滚什么」是从有限几个人的样本概括的。
- 「对，就是这个意思」的口径只定了方向，严格口径读数今天几乎全 0。
