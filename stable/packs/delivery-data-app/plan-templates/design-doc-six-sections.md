# 设计稿 · 六段模板（v0.1，2026-09-23）

> 动手前让 harness 先写这份，写完再改代码。六段里**「验收」和「不变量」必填**，其余可短。
> 为什么是六段：前四段回答「做什么」，动作清单管得住被点名的地方；后两段回答「做对没」和「不许碰什么」，只有它们管得住 harness 自己新写的东西。
> 层级对照（设计文档四层 + 一执行轴）：全景 → 目标；架构 → 口径 + 数据源；模块 → 分步；约束 → 不变量；执行轴 → 验收。

```markdown
# <系统或功能名> · 设计稿（<日期>）

## 1. 目标
一句话：给谁、解决什么、做到什么程度算完。引用使用者的原话，不改写。

## 2. 口径
这件事里由人定的判断（什么算异常、什么算完成、阈值多少）。逐条写「谁定的、原话、日期」。
没定的写「待裁」，不准 AI 代定。

## 3. 数据源
读哪些现有系统 / 表 / 文件；只读还是可写；写的话白名单是什么。
已经自洽的数据直接接，不另建平行数据源。

## 4. 分步
按顺序列步骤；每步一句「做什么、产出什么、谁验」。一步做不完就拆。

## 5. 验收（必填）
每条 = 一句判据 + 一条能跑的命令（退出码 0 = 过）。至少引用 .agents/rules/data-app-norms.md 两条。
- [ ] <判据>  ——  `<命令>`
- [ ] <判据>  ——  `<命令>`
- [ ] 页面过产物规范检查器  ——  `python .agents/validators/data-app-norms-check/scripts/check_data_app_norms.py --changed`

## 6. 不变量（必填）
这个仓从此要一直成立的事，harness 新写的代码也得守：
- 例：所有页面离线可开（零外部依赖）
- 例：写动作只限白名单，不可逆动作先确认
- 例：不改动 <某目录> 下的口径文件
```

## 用法

1. 复制到项目的 `docs/design/<日期>-<题>.md`，填完再动手。
2. 「验收」里的命令，做完逐条跑；跑不过不算完。
3. 交给另一台机器或另一个 harness 执行时，只交这份；对方读它，不读你的聊天记录。
