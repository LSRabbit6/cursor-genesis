# domain-menu · 领域清单入口（v0.1，2026-09-23）

> 这是发布态的入口：没有人替你推演，你在清单上选，清单告诉你我们有什么、你要给什么。
> 铁律：不替你定业务口径；清单里写的是**模式**不是做法；给不出的直接写「空白」，不编。

## 二、空白领域流程（选了「其他」）

1. **先承认空白**：告诉使用者这个领域我们没有沉淀，接下来给的是领域无关的骨架，不是领域知识。
2. **四格骨架**（能给的）：
   - 观测：先读使用者的「期望状态」（他认为什么算做好）再看现状；规则按权威度取材——现有系统肯接受的结构 > 访谈 > 历史数据；按「组织层 → 单位层 → 岗位层」分层看。
   - 边界：第一版只做协调（读取、通知、记录、收回执），不给写权限；写动作先白名单、可逆优先、不可逆走人工确认；口径只由使用者定；系统解决不了激励和考核问题，别承诺。
   - 规范：先问真意图再出方案；两头开放中间固定——目标由人定、现场例外由人判，中间用规则表和配置按确定规则流转；先接已有的权威数据源，不另开一套。
   - 比较器：验收三件套 = 事前写好的口径 + 程序从原始数据复算的结果 + 两者的差；判对错的是使用者不是 AI；口径分两轮采（先讲机制，再对着结果定边界）；每周要人判的次数有上限；偏差检测要带「结果不该全干净」的反向用例；关掉 AI 后日常仍能按手册跑。
3. **SOP 格留空**：每一步在这个领域里具体怎么做，我们给不了——那要用使用者的材料在他的环境里现场做出来。**让他填材料清单**：

   ```text
   材料清单（请逐项给，给不出的写「给不出」）
   1. 现有系统清单，以及各自能导出什么数据
   2. 制度 / SOP / 表单模板（有什么给什么）
   3. 组织架构与岗位（谁看什么、谁能改什么）
   4. 法规或行业红线（哪些东西不能碰、不能存）
   5. 本期最痛的三件事，按顺序；本期目标与时间窗
   6. 指标清单：名字、口径、阈值；行业正常区间（不知道就写不知道）
   ```

4. **输出 spec 骨架**（占位符必须由材料填，不许 AI 自行补）：

   ```yaml
   goal: "为 <使用者> 的 <对象清单> 建 <系统名>：<首要目标> 在 <时间窗> 内由 <指标> 从 <基线> 到 <目标值>，且使用者能用自己的话复述每个指标的判断逻辑"
   constraints:
     - "只做协调优先：默认只读 <现有系统清单>；写动作限于 <动作白名单>，不可逆动作走人工确认"
     - "口径只来自 <使用者或其指定岗位>；未确认口径标「待裁」，不进判定和看板"
     - "中间流转按确定规则判定；LLM 只做 <自然语言录入> 与 <结果解释> 两端"
     - "<法规 / 安全红线清单> 原样保留"
     - "<现有系统> 中已自洽的数据直接接入，不另建平行数据源"
   acceptance_criteria:
     - {criterion: "指标由独立脚本从原始数据复算且一致", check: "<一条可跑的命令，退出码 0 = 过>"}
     - {criterion: "上看板的指标都有使用者确认记录", check: "<命令>"}
     - {criterion: "偏差检测不只报喜：注入已知异常必须被报出", check: "<命令>"}
     - {criterion: "每周需使用者逐条判断的次数不超上限", check: "<命令>"}
   ```

5. **回流**：把第 3 步的材料清单（含「给不出」的项）和使用者选的领域名，原样贴到 [cursor-genesis 的 issue](https://github.com/SYMlp/cursor-genesis/issues) 或按 `docs/downstream-spec.md` 走 `.knowledge/downstream/`。这是我们下一章该写什么的唯一依据；不回流，清单永远是骨架。

## 三、动手之后
