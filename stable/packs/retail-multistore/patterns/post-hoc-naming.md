# 模式 · 事后名称整理（v0.1.0）

> 日常办理时，员工怎么叫就先怎么记：费用名、商品名、收款方都留原话。事后由**被授权的人**看着统计和 AI 建议，把这些原名整理成标准细类和别名；整理结果下一笔就能认出来。
> 解决的现象：一开始想把分类一次做细，结果日常办理卡在「选不出细类」；或者随手归进「其他」，月底谁也说不清「其他」里是什么。
> 适用：费用细类、商品对应、收款对象这类「名字多、标准晚到」的东西。不适用：已经有稳定编码、员工照着选就行的对象。

## 1. 目标（并进设计稿第 1 段）

- 日常办理只要求第 2 段定下的必填项，细类、商品规格不当门槛。
- 原名、事由、原话里的收款方和大类，连同来源，一条不丢。
- 整理过的名字下一笔就能用；撤回或停用之后，旧建议不再生效。

## 2. 口径（并进设计稿第 2 段，全部〔待裁〕）

| 〔待裁〕 | 常见候选（只是帮你想全） |
|:--|:--|
| 谁能整理分类 | 先只给老板；以后要扩给谁，单独授权。不因为岗位叫会计、出纳就自动有整理权 |
| 细类在哪个时点必须有 | 不要求 / 店长审核时补 / 付款后、结账前补齐 |
| 日常大类从哪个范围里选 | 本店已有的统计科目里，先排除固定费用和系统自动算的，剩下的少数几项 |
| 结账前还有没整理的怎么办 | 必须清零 / 允许带着「待整理」结账，单独列一栏 |

「付款后仍待分类」要有明确授权的通道，不能拿随手填「其他」冒充已归类。

## 3. 数据源与对象（并进设计稿第 3 段）

先分清这五样**不是同一个东西**：费用大类、细类、会计科目、外部系统（ERP）的类目、商品。设计稿里每提到一个「分类」，写明是哪一样。

仓里已经有分类库的，复用它，不另起第二份正式分类库。需要新增时：

| 对象 | 最少记什么 | 为什么 |
|:--|:--|:--|
| 名称观察 | 观察编号、单据和材料版本、范围、原名、上级候选、来源、有效状态 | 原名是事实；同一单 AI 重跑不算新的一笔 |
| 标准细类 | 稳定编号、上级、名称、别名、作用范围、版本、有效状态、人工决定依据 | 改名不换编号；合并保留原引用和历史 |
| 整理决定 | 请求号、操作人、选中的观察、预览摘要、前后版本、动作、回执 | 能回查、能更正、重复提交只生效一次 |
| 商品候选 | 来源、商品编号、编码、名称、规格、单位、资料版本、未核实项 | 和细类分开；只有核实过才确认对应 |

## 4. 分步（并进设计稿第 4 段）

1. **先能查。** 做一个能检索的「临时名称」列表：按原名、门店、时间、状态筛选，每个名字能点回原单。
2. **再给建议。** 程序统计每组的笔数、已知金额合计、样本；AI 只建议怎么归组、标准名叫什么、别名有哪些。**建议不是正式名称。**
3. **人看着预览确认。** 一组名字能看到：原名、适用范围、已知金额、原件。可以做的动作：指向已有细类、新建细类、合并细类、加别名、拆开这一组、暂缓、拒绝建议。确认前先显示「这样改会影响哪些单」。
4. **一组确认是一个事务。** 所选观察和标准对象任一处冲突，整组拒绝，要求重新预览，避免半组改了名。（这和角色待办的批量审批不同：审批是逐笔回执，整理是整组成败。两种语义别混。）
5. **发布成有效知识。** 确认后生成下一笔识别能查到的投影。确认成功、投影发布成功、下一次查询真的命中，三件事分别留证据，不只看界面上的「保存成功」。
6. **撤销用追加。** 撤销是追加一条更正决定和新版本，重新计算依赖它的投影；不改原单，不改已发生的金额和付款。
7. **月度视图。** 分开显示未整理、已整理、待核对、实际付款四种状态，并固定用的是哪个版本的分类。

## 5. 验收（并进设计稿第 5 段，挑至少三条）

| 场景 | 必须看到的结果 |
|:--|:--|
| 员工报了一个分类库里没有的费用名 | 单据照常往下走；原名留着，状态是「待整理」，不被塞进「其他」 |
| 整理人把三个原名合并成一个细类 | 先看到影响了几笔；确认后三个原名都成了别名；原名和历史决定还在 |
| 下一笔用了其中一个原名 | 识别直接给出已确认的细类 |
| 撤回这次合并 | 之后的新单不再引用旧建议；已发生的金额、付款事实不变 |
| 跨店整理（没有那家店的权限） | 被拒绝 |
| 同名但规格不同的两个商品 | 不自动合并；要核实编号和单位后才能确认对应 |

## 6. 不变量（并进设计稿第 6 段）

- 新增或改名一个细类，不顺带改会计科目，也不改金额。
- 服务类费用（打车、维修这类）不硬配商品。
- 不确定就保留临时名称或「待确定」，不自动塞进「其他」。
- 正式分类只经同一个入口写；别的模块、别的机器要改，也调这个入口，不直接写分类表。
- 待分类的金额照样进「已发生支出」和「未归类」汇总，按科目汇总时不能悄悄漏掉。
- 费用流水推不出真实库存和成本；盘点、损耗、单位换算要另有来源和口径。

## 常见走偏

- 一上来就要求每类都有完整字段和材料标准，日常办理跟着卡住。分类可以晚到，办理不能等。
- 让 AI 在结账前自动选一个细类凑齐账。
- 把「同名」当成「同一个商品」。
- 整理页面改了名，但识别那边还在查旧表，下一笔照样认不出来。
