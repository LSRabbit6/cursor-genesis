# domain-menu · 要方案的入口（v0.2，2026-09-24）

> 推演在你这边：你读自己的仓、答清单、定类型。服务那边不推演，只查表——有包回包，没有就登记、回编号。
> 服务只管「拿」，不管「跑」：装进来的东西都在本仓里，服务停了照样能用。
> 下面的 `menu.py` 都指 `python .agents/skills/domain-menu/scripts/menu.py`，在项目根目录跑。

## 一、要方案（五步）

1. **拿清单**：`menu.py checklist`。打印出规矩、要答的几问、类型表和一份 JSON 模板。
2. **自查**：逐问答，只从本仓文件和用户原话里取；答不出写「给不出」，不猜。业务口径（什么算异常、谁能看谁的）只抄用户原话，没有就写「待用户定」。类型从表里选 id，可以多选：这次的活一类、所在行业一类。答案按模板写成 JSON，存到**仓外**的临时文件。
3. **交回**：`menu.py submit <那个文件>`。客户端会自动带上本仓已装的包和版本。
4. **按回执做**：
   - `✔ 有包`：照回执的命令 `menu.py install <包名>`；再把回执里每一条「设定」贴到它说的位置（AGENTS.md 指针、收工 hook）。装完 `git status` 看落了哪些文件，跟用户说一句装了什么、多了什么。
   - `△ 只有骨架 / ○ 我们没有`：把编号告诉用户；按回执里的骨架先干，骨架的占位符只能用用户给的材料填，不许自己补。选了 other 而六项材料没填全的，列出来问用户，问到了再 submit 一次。
5. **过几天**：`menu.py status <编号>`。变成 `有包` 就回到第 4 步装。

## 二、用着不合身

规范哪条在这里不对、检查器误报或漏报、想要一个新东西：

`menu.py feedback --category misfit|validator|want --where <页面或文件> --text "<用户原话或你看到的现象>"`

只记不判：不绕过检查器、不改 `.agents/` 里装进来的文件（下次一装就被覆盖）。

## 三、连不上服务

`submit` / `feedback` 连不上时，要交的内容会存进 `~/.config/cg-menu/pending/`，联网后 `menu.py resend` 补交。**别等，手上的活照做。**本仓如果另有约定的纸面收件箱（比如 `docs/组件请求收件箱.md`），也可以按它的格式记一条。

## 四、令牌

交东西、查编号要令牌：环境变量 `CG_MENU_TOKEN`，或文件 `~/.config/cg-menu/token`（一行）。令牌不进仓、不贴进提交。拿清单、看包、装包不用令牌。服务地址默认 `https://menu.lsrabbit.space`，`CG_MENU_URL` 可改。

## 负空间

- 服务在我们的一台机器上，不保证 7×24；连不上走第三节。
- 类型表现在五类：一类有包（数据应用后台）、一类能读装不了（企业交付）、两类只有模式名（零售、病理）、一类是空白（其他）。空白和骨架的，登记就是我们下一章写什么的依据。
- 客户端只用 Python 标准库；装包用包里自带的安装器，装法与 `install-pack.py` 从 GitHub 装完全一样。
