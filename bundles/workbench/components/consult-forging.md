# 组件说明 · 聊天记录锻造（〔临时名〕consult-forging）

> 属于：工作台包 0.2.0 起。条件标签在 [../bundle.yaml](../bundle.yaml)：`basis` 钉 kg 方法 `knowledge-graph:methods/chat-record-forging.md@2026-10-22`（draft）。
> 给谁看：收件人电脑上的 AI 照这份装；维护者自己在客户目录里跑，也照这份。
> 一句话：拿一个人的聊天记录当原料，按「会谈 → 一问一答 → 分堆 → 分类 → 客户过目 → 出口」锻造出给他用的东西。分类先给本人看，本人认了才往下提炼。

## 1 六步

| 步 | 输入 | 输出 | 谁判 |
|---|---|---|---|
| 会谈 | 聊天记录、会议转写，加维护者会后写的一段工作方式概述 | 第 0 层原料，原样存，只增不改 | — |
| 一问一答 | 第 0 层 | 每条消息标上第几轮、谁说的 | 程序 |
| 分堆 | 一问一答 | 按事情分堆：一堆一件事，列出用到的轮次 | AI 出候选 |
| 分类 | 每一堆 | 场景（九选一）加一句「实际要的是什么」 | AI 出候选 |
| 客户过目 | 分堆、分类、偏好、案例 | 一张待过目清单；每条记认、不认、改 | 客户本人 |
| 出口 | 提炼两栏 | skill 候选、客户的偏好、案例、范式读数 | 维护者拍 |

提炼夹在分类和出口之间，拆两栏：
- 左栏「我说的方法」：只收维护者自己说出来的做法、标准、分法、规矩。每条带出处轮次和逐字原话，原话对不上的作废。
- 右栏「方法框架上提炼出来的结果」：拿工作方式当框架，把每一堆的细节填进七格。七格是：客户讲问题、他说理解、客户认不认、他讲 AI 怎么做、演示、客户反馈、临时想法。没有的格留空，不补。

## 2 两个座位

| 座位 | 在哪台电脑 | 跑什么 | 拿到什么 |
|---|---|---|---|
| 使用方（专家） | 自己的电脑，装工作台包 | 拿自己跟 AI 干活的聊天跑前五步 | 给自己干活用的 skill、自己的偏好档案 |
| 维护者 | 维护者的电脑，客户目录里 | 拿会议转写、概述跑全程 | 教自己怎么跟这类人沟通的 skill、案例、范式读数 |

- 使用方的聊天记录不离开使用方的电脑。
- 维护者那边只收客户认了的案例，只写角色，不写人名。
- 两边用同一份骨架，第一次由维护者带着跑，「现在客户引导维护者，成熟后维护者引导新人」。

## 3 装成什么样

在工作台里建一个目录 `consult/`：

```text
consult/
  CASE.yaml        # client 只写角色；kind 是哪一类人；direction、paradigm_threshold 照抄本节
  raw/<会谈>/      # 第 0 层：turns.jsonl（一问一答）、overview.md（概述）。只增不改
  ledger/          # 各层的账，一行一条，只追加：sources、heaps、digs、review、batches，加运行记录
  layers/          # 提炼两栏的投影，可重出
  review/          # 待过目清单，给客户本人看
  exits/  cases/   # 出口；案例一条一个文件
  progress/        # 进度线投影（可选）
```

- 每层落盘。提炼件写明它提炼自哪一层的哪几条（依据边），要用时才往深提。
- `CASE.yaml` 两行照抄：`direction: 现在客户引导我，成熟后我引导新人`；`paradigm_threshold: 积累多了，按读数定`。

## 4 每一步的规矩

1. **会谈进件**：原稿只增不改；同一个会谈编号、内容变了就拒。进件前扫一遍密钥，命中整场不进。
2. **一问一答**：提问的那一方每重新开口一次，算新的一轮；旁人插话不断轮；同一轮同一人的几段并成一条。只有维护者和客户的话算断言，AI 的回答是旁挂。
3. **分堆、分类**：一场 1～6 堆；一轮只进一堆；寒暄不进堆。场景从九个里选（弄想法、打磨体系、调研、学习、给真人交付、看别人发来的、复盘、收割、其他）。这一步可以用出候选档的模型，条件是：产物只是候选、选项是封闭的、回执按 schema 校验。
4. **客户过目**：
   - 不默认通过。没回的一律算没认，放多久都不变。
   - 「改」要记客户的原话。
   - 这张清单不进任何「几天不否就算过」的收件箱。
   - 这道阀是挖需求的地方，不是验收。
5. **提炼**：用强思考档。原话逐字比对由程序做，对不上的不进出口。
6. **出口**：skill 只列名字、来源、建议放哪，不建；客户的偏好另列；案例一条一个，对外讲之前要客户认；范式这一层只出读数（同一类人攒了几个客户、几条案例、客户认了几条），不出正文。

## 5 宿主那一层

每一步拉一个新会话跑，不续接旧会话。每步要给的四样：单独的系统提示、限定的工具和目录、回执的 JSON schema、花费封顶。
- Claude Code、Codex 各自怎么写这四样，看 [adapters/claude-code/README.md](../adapters/claude-code/README.md)、[adapters/codex/README.md](../adapters/codex/README.md)。这份说明不写型号、不写命令。
- 宿主会在自己的目录里留下会话记录。收件人要知道它在哪，不要把它当成 `consult/` 的一部分搬走。

## 6 现场验收

装完，对方 AI 要能做到：
1. 拿一份没有敏感数据的旧聊天，进件成 `raw/<会谈>/turns.jsonl`，说出一共几轮、谁说了几次。
2. 出一张待过目清单，每条有编号，状态全是「待过目」。
3. 使用方回一条「改」，AI 记下原话；再出一次清单，那一条的状态变了，别的没变。
4. 出口里能分清 skill 候选、偏好、案例三样；没认的标着「待过目」。
5. 关掉重开，能说清上次跑到哪一批、哪几条还等客户回。

## 7 不做

- 不替客户认分类。
- 不把使用方的原始聊天带回维护者那边。
- 不在积累够之前写范式正文；「够」看读数定，不先写一个数。
- 不在这份说明里写人名、型号、命令。
