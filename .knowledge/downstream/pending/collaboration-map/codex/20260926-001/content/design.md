# 双视角协作图设计

## 目标

让使用者先看整体架构，再沿同一环节对照 CG 供给侧和项目客户端的职责、交接内容与证据。把已存在、已观察但不在本仓、尚未验证三种状态分开。

## 口径

使用者要求“先一个整体架构图，在整体架构图下面，一方面是服务端视角，一方面是客户端视角”。这里的服务端指供给与维护侧；在线服务是可选分发方式。判断与实施在项目中进行，业务决定归使用者，通用资产回流由 CG 维护者判断。

## 数据源

本仓 AGENTS.md、README、安装器与测试、delivery-data-app 0.1.0 的清单、技能、检查器契约，以及 downstream-spec。在线菜单内容仅由下游实际使用过的 0.2 客户端与回执支持；没有在本仓发现服务端源码，不从接口猜测数据库或后台调度。

## 步骤

保留旧架构快照；重写当前 architecture.md；增加零外部依赖、可离线打开的阅读页面；从 README 和下游规范接入。在线菜单单列为下游观察。整理回流提交说明和验证记录。

## 验收

- 总图后能直接看见服务端 / 客户端两种视角，六个环节均包含职责与交接内容。
- 已安装 / 已加载 / 已触发 / 已检查通过明确分开，源码交付和正式部署不混用。
- 浏览器测试 320px、390px、桌面、键盘与展开行为；无横向溢出、无外部网络请求、无脚本错误。
- 运行数据应用规范检查器检查 docs/collaboration-map.html；用本地路径校验确认新增文档的链接存在。
- 运行既有安装器测试，确认文中对应的分发入口仍通过现有测试。

## 不变量

不修改包版本、规范与检查器；不改变业务口径、上层治理归属或宿主权限；不实现未取得源码的菜单服务；不把下游私有信息、真实票据、凭据和机器路径提交到公开仓。本文与页面是可评审的文档改进，不自动发布或部署任何业务服务。
