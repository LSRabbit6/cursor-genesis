# CG 维护闭环：权限、回流和可重复验证

## 1. 问题与目标
现有工作台可运行，但令牌不能限制操作或到期，反馈与仓库回流断开，验证和备份依赖人工拼命令。本轮补齐可执行流程并提交；公网域名和主机尚未指定，不宣称完成上线。

## 2. 使用者与场景
维护者在网页给不同接入签发、调整、撤销令牌，查看使用时间；客户端继续使用同一 HTTP / Python CLI 契约。维护者将反馈整理为可公开摘要后导出，维护 Agent 导入候选目录，经审核关联 PR，再按真实结果处理记录。

## 3. 结构与交互
令牌入口增加操作范围和到期时间，列表显示状态、范围和最后使用时间。反馈详情增加六项回流摘要、公开确认、下载及 PR 关联；导出历史保留在原编号下。表单失败保留输入，成功有回执；390px 保持单列可读。

## 4. 数据与兼容
新增令牌 scopes、expires_at、last_used 列。既有令牌保持原权限且永不过期；维护者可原地收紧或重新签发。服务端按每个动作执行权限检查。回流导出只用维护者新填的六项摘要和来源编号，不自动复制原始项目名、自查或事件正文，也不自动推到公开仓库。导入拒绝覆盖、非法编号和多余字段。

## 5. 验收
统一入口运行构建、Node/Python 回归、页面规范、发布清单校验和迁移一致性；GitHub Actions 调用同一入口，成功才保存可部署产物。新增回归覆盖旧库升级、只读拒写、范围与项目隔离、到期/撤销、回流隐私与幂等、真实备份恢复。页面遵守数据应用规范的零外部依赖、动作回执、错误保留输入及手机布局。命令：`pnpm verify`；恢复演练由 `service/tests/maintenance.test.mjs` 实际执行。CI 与发布检查不等同于所有 stable 资产认证。

## 6. 不变量与交付边界
公共契约不绑定任何模型平台；不读取业务后台、不替项目决定业务口径；网页零外部依赖；不将私有材料自动公开；失败不覆盖现有备份或恢复目标；已发布包内容改变必须提升版本；不伪造真实 harness 插件验证或公网 TLS 验证。稳定项目 ID、项目重命名和多人账号属于单独的数据模型迁移，本轮不以令牌权限功能冒充完成。
